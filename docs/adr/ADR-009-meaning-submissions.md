# ADR-009：释义投稿、管理员审核与补充词书

- **状态**：已接受
- **日期**：2026-11-01
- **范围**：外部学习系统向 Lexarbor 提交词库里没有的释义，由管理员审核后写入一本补充词书。

## 背景

接入 Lexarbor 的学习系统（例如 Ruoyu.Study 的学生生词本）需要让学习者添加任何词书里都没有的词或释义，同时希望单词、音标、释义和发音仍由 Lexarbor 统一管理，而不是在接入方另存一套词库。Lexarbor 原有写入口只对管理员开放，公共 API 只读且匿名；Lexarbor 也没有学习者身份的概念。

## 决策

1. **投稿单独存放，不进入任何词书**。新表 `meaning_submission` 记录拼写、词性、释义、例句、提交方和状态（待审、已通过、已驳回）。拼写、规范化词性、去空白释义都相同的待审投稿只保留一条，重复提交返回同一条。
2. **只有一本补充词书**，由部署配置 `MeaningSubmissions:BookId` 指定。管理员通过投稿时，用与导入相同的匹配规则把（可能修改过的）释义写入这本书，拼写已存在时复用单词行；同一事务内把投稿标记为已通过并记录结果位置。未配置时投稿和审核都不可用。
3. **管理员在 Lexarbor 管理端审核**。可修改单词、词性、释义、例句并补音标；通过后的单词可以照常上传发音。驳回不填原因。
4. **AI 只给建议**。可选配置 OpenAI 兼容的 chat-completions 端点（默认关闭）。管理员点击后，Lexarbor 只把投稿文本发给模型，返回建议的结论、释义和音标；是否通过由管理员决定，AI 不可用不影响人工审核。
5. **集成接口用服务令牌认证**。`/integration/meaning-submissions` 只接受一个接入方用部署私钥逐请求签发的 RS256 短期 JWT：已登记 kid、固定 issuer/audience/subject、单一 iat/nbf/exp、寿命不超过 60 秒、时钟偏差 5 秒、scope 含 `meaning-submissions`。Lexarbor 只加载公钥 ring，不联系身份提供方、不保存客户端密钥。管理员凭据不能访问集成接口，服务令牌也不能访问管理接口。公共 `/api` 保持匿名只读，不受影响。
6. **待审投稿可以出题**。题干和正确选项用投稿文本，干扰项从全部启用词书抽取。已通过且拼写、释义未被修改的投稿通过补充词书里的释义出题；被修改或驳回的投稿不再出题（404）。补充词书本身出题时，若书内干扰项不足三个，从其他启用词书补足；其他词书的出题规则不变。
7. **Lexarbor 不保存学习者身份**。投稿只记录提交方（服务令牌的 subject），谁在学这个词只在接入方保存。

## 方案取舍

- **每个学习者一本词书**：公共书目会暴露学习者的生词清单，书的数量随学习者增长，单本书也无法凑齐干扰项。拒绝。
- **待审内容直接写入补充词书或另建待审词书**：前者让未审内容对所有人可见；后者审核时释义跨书移动，ID 变化迫使接入方重新定位。拒绝。
- **复用 SignaCore 客户端凭据**：会让集成调用依赖身份服务在线，接入方也要新增运行时依赖。选择本地公钥 ring，与接入方已有的服务身份做法一致。
- **由 Lexarbor 自动调用 AI 决定**：错误释义会无人复核地进入公共词库。拒绝，AI 只做建议。

## 后果

- 新增 SQLite 迁移 `AddMeaningSubmissions`（只新增一张表和索引，不改已有数据）。回退到旧版本时该表被忽略；迁移 Down 删除该表和其中全部投稿。
- 新增配置 `MeaningSubmissions:*`；全部未配置时功能关闭，现有部署行为不变。
- 管理端新增「投稿审核」页面。
- 管理员修改释义文字会让接入方已在学这条释义的学习者重新学习（接入方以释义文字识别学习记录）。
